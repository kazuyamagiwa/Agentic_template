# 🤖 自律型 AI エージェント コンテキスト＆メモリフレームワーク

> **AI 支援ソフトウェア開発向けの、トークン最適化・マルチモデル対応テンプレートリポジトリ。**  
> API クレジットの浪費、セッション途中でのコードベース把握の喪失、手動テストデータの作成に何時間も費やすことをやめましょう。

---

## 🌟 主な機能

* **🧠 デュアルメモリアーキテクチャ（圧縮 JSON キャッシュ）:**
  * **短期セッションキャッシュ（`memory-shortterm.md`）:** 作業日中の直近タスクと未コミット変更を追跡。入力トークンの肥大化を防ぐため毎日フラッシュします。
  * **長期エポックキャッシュ（`memory-longterm.md`）:** マクロアーキテクチャと完了マイルストーンの、不変で圧縮された履歴。
* **⏱️ 動的オートノミー・スロットリング:**
  * **ペアプログラミングモード**（50 行 / 主要コンポーネントごとに厳格に一時停止）と **夜間自律モード**（中断なしのマルチファイル実行）をシームレスに切り替え。
* **🔍 マルチモデル識別＆レッドチーム監査:**
  * どの LLM モデルがどのセッションを実行したかをメモリログに記録。
  * コミット前にセカンダリモデル（例: Claude 3.5 Sonnet を OpenAI o1 がレビュー）を使う、オプションのレッドチーム監査ワークフロー。
* **🧪 必須「トライアド」検証:**
  * AI にソースコードと同時に、**ハッピーパス**、**エッジケース**、**失敗パス**のダミーデータを含む自動ユニット／統合テストの生成を強制。生の `console.log()` による検証を禁止。
* **📚 リビング ReadTheDocs 同期（`/docs`）:**
  * 人間が読めるドキュメント（`/docs/architecture.md`、`/docs/api.md`、`/docs/setup.md`）を継続的に更新し、AI のコア動作コンテキストを散らかさない。
* **🔌 ネイティブ IDE バインディング:**
  * **Cursor**（`.cursor/rules/`）、**GitHub Copilot**（`.github/copilot-instructions.md`）、**VSCode**（`.vscode/tasks.json`）向けのネイティブ設定サポート。

## 🚀 クイックスタートガイド

### 1. ワークスペースの初期化
このリポジトリをクローンするか、GitHub テンプレートとして使用します。ターミナルで初期化スクリプトを実行し、`.agent/active/` ディレクトリを安全に準備します:

```bash
chmod +x init.sh
./init.sh
```

### 2. 対話型 AI セットアップの実行
AI コーディングアシスタント（Cursor、Claude Dev、ChatGPT、Aider、GitHub Copilot など）を開き、次のプロンプトを貼り付けます:

> *「`.agent/setup.md` を読み、9 問のセットアップインタビューを実施してください。」*

次の質問に答えてください:
1. **プロジェクトビジョン** ＆スコープ
2. **テックスタック** ＆フレームワーク選択
3. **禁止パターン**（避けるべきアンチパターン）
4. **テストフレームワーク** ＆配置
5. **ディレクトリ境界**
6. **モデルツールチェーン** ＆レッドチーム監査の設定
7. **オートノミー・スロットル**（50 行ペアリング vs 夜間モード）
8. **IDE 統合**（Cursor / Copilot / VSCode）
9. **リビングドキュメント**（`/docs` の ReadTheDocs）

AI はカスタマイズされたコンテキストファイルを `.agent/active/` 内に自動生成します。

## 🛠️ コアコンセプト

### 「記憶喪失ルール」＆デュアル トークンキャッシュ
大規模言語モデルは、会話が長くなるにつれてコンテキスト喪失とクレジットコスト上昇に悩まされます。
* これを解決するため、新しいコーディングセッションはすべて **記憶喪失ルール** のもとでまっさらな状態から始まります。
* AI はコンテキストを厳密に `.agent/active/memory-longterm.md`（高レベル JSON アーキテクチャ状態）と `.agent/active/memory-shortterm.md`（アクティブな JSON タスク状態）から再読み込みします。
* 長い会話履歴は再読込しないため、入力トークンのオーバーヘッドを最大 **80%** 削減します。

### トライアッド・テストプロトコル
行ごとの手動デバッグやターミナルの `console.log()` は時間の無駄です。AI は、次の 3 種類のダミーデータプロファイルを含むテストを出力することで、コードが動作することを証明する必要があります:
1. **ハッピーパス:** 期待される入力フォーマット。
2. **エッジケース:** 空集合、null、境界値、極めて長い文字列。
3. **失敗パス:** エラーハンドラを意図的にヒットさせる不正な型や未認可アクセス。

### モデル識別と説明責任
プロジェクト途中でモデルを切り替える場合（例: アーキテクチャに Claude 3.5 Sonnet、クレジット節約のため Ollama 経由のローカル Llama-3、コードレビューに GPT-4o）、AI は正確なモデルバージョンを `.agent/active/memory-shortterm.md` に記録します。バグや構造ドリフトが発生した場合、どのモデルが導入したかを監査できます。
