# リビングドキュメントプロトコル（ReadTheDocs）

**システムディレクティブ:** コードベースと同期した、人間が読めるプロジェクトドキュメントの維持に責任を持ちます。

## 1. ドキュメント範囲
*   **ドキュメントスタイル:** {{DOCS_STYLE}}（例: `/docs` ディレクトリ内の Markdown ファイル）
*   **更新頻度:** {{DOCS_UPDATE_FREQUENCY}}（例: 毎セッション終了時、または主要マイルストーン時）

## 2. メンテナンスルール
コアビジネスロジックを変更し、新しいエンドポイントを追加し、またはデータベーススキーマを変更するときは、必ず次を行うこと:
1. 構造設計やデータフローが変わった場合、`/docs/architecture.md` を更新する。
2. 新しいペイロード、ヘッダー、レスポンス形状を `/docs/api.md`（または同等の OpenAPI／Swagger ファイル）に更新する。
3. 環境変数、前提条件、インストール手順が変わった場合、`/docs/setup.md` を更新する。
4. ドキュメントは明確な Markdown 見出し、サマリー表、Mermaid.js のシーケンス／フロー図を使うこと。
