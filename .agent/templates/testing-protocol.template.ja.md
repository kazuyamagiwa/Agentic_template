# 自律検証＆テストプロトコル

**システムディレクティブ:** コードが動作することを証明する義務があります。作成または変更する論理コンポーネント、関数、API エンドポイントごとに、同時に自動検証を生成しなければなりません。人間が print 文でデータフローを手動テストすることに頼らないでください。

## 2. 「トライアッド」ダミーデータルール
テストを書くときは、必ず次の 3 種類のダミーデータセットを生成すること:
1.  **ハッピーパス:** 完璧にフォーマットされた、期待どおりの入力。
2.  **エッジケース:** 空配列、null 値、0、または極めて長い文字列。
3.  **失敗パス:** 不正なデータ、無効な型、または未認可のユーザー ID。

## 3. 厳格なアサーションルール
*   **コンソールログ禁止:** データの検証に `print()`、`console.log()`、`echo` を使わないこと。明示的なアサーション（例: `expect(result.data).toEqual(dummyData)`）を使うこと。
*   **ステータスだけでなくデータ形状を検証:** 返却ペイロードが期待どおりのキーと型に一致することをアサートすること。
*   **外部境界をモック:** データベースと外部ネットワークエンドポイントをインターセプトすること。

## 4. 実行ワークフロー
機能ブロックを完了したら:
1. ダミーデータとテストが書かれていることを確認する。
2. ターミナルアクセスがある場合は、テストスイートを実行して出力を検証する。
3. テストが失敗したら、メモリを更新してセッションを終了する前にソースコードを修正する。
